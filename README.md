# מערכת לניהול ועיבוד דוחות נוכחות (Attendance Report Pipeline)

פרויקט זה נועד לאפשר מעבר מצינור נוקשה ל-**ארכיטקטורה פולימורפית ומודולרית** (Pipeline) המטפלת בדוחות נוכחות מסוגים שונים (סוג A וסוג B) בצורה חלקה, תוך הפרדת רשויות נוקשה שבה שלבי הצינור המתקדמים נותרים אגנוסטיים למקור ה-PDF.

---

## 🏗️ ארכיטקטורת הצינור (Pipeline Architecture)

הצינור מנוהל בשלבים הבאים:

1. **OCR / קריאת טקסט (`ocr_reader.py`)**
* **מה נכנס:** קובץ PDF סרוק או תמונה.
* **מה יוצא:** מחרוזת טקסט גולמית.


2. **זיהוי סוג הדו"ח (`classifier.py`)**
* **מה נכנס:** מחרוזת טקסט גולמית.
* **מה יוצא:** זיהוי סוג הדו"ח (`ReportType.A` או `ReportType.B`).


3. **פרסור וחוזה (`parsers.py` & `models.py`)**
* **מה נכנס:** מחרוזת טקסט גולמית.
* **מה יוצא:** אובייקט דו"ח תקני (`AttendanceReport`) העומד בחוזה אחיד. מכאן והלאה השלבים הבאים אינם צריכים לדעת באיזה סוג PDF מדובר.


4. **טרנספורמציה והגרלה (`transform.py`)**
* **מה נכנס:** אובייקט הדו"ח המקורי.
* **מה יוצא:** אובייקט דו"ח חדש שעבר וריאציה, מיון ובקרת תקינות (מבלי לשנות את המקור).


5. **גנרוט פלטים (`generate.py`)**
* **מה נכנס:** אובייקט הדו"ח המעובד.
* **מה יוצא:** קובצי PDF מעוצבים ונקיים הנשמרים בתיקיית היעד.



---

## 📁 מבנה הקבצים בפרויקט

* **`main.py`** – הלב של המערכת; מנהל את זרימת הצינור מקצה לקצה בהתאם לסוג הדו"ח שזוהה.
* **`classifier.py`** – זיהוי חכם של סוג הדו"ח מתוך טקסט ה-OCR.
* **`parsers.py`** – מפעל (Factory) ופרסרים ייעודיים הממירים טקסט גולמי למודלי נתונים מובנים.
* **`models.py`** – הגדרת מבני הנתונים (Dataclasses), מודלי השורות ולוגיקת הוולידציה העסקית.
* **`transform.py`** – אלגוריתמים להגרלה, סידור כרונולוגי, מניעת חפיפות וחישוב מדרגות שעות (100%, 125%, 150%).
* **`generate.py`** – הפקת קובצי ה-PDF באמצעות ספריית `ReportLab`, כולל תמיכה בעיצוב עברית ותבניות טבלאות מותאמות.
* **`ocr_reader.py`** – עיבוד תמונה וקריאת טקסט.

---

## 🚀 הוראות הפעלה

1. ודאו שכל הספריות הנדרשות מותקנות בסביבת העבודה (Python Virtual Environment).
2. עדכנו את נתיב קובץ המקור ב-`main.py` תחת המשתנה `CARD_PATH`.
3. הריצו את הסקריפט הראשי:
```bash
python main.py

```


4. הקבצים המופקים ייומנו וישמרו אוטומטית בתיקייה **`generated`** תחת פרויקט הבסיס.
